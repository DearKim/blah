# 제품 페이지 (`/products`, `/products/:slug`)

두 페이지의 시안을 한 문서에 정리합니다. 둘 다 동일한 데이터 소스([`src/content/products.ts`](../architecture/content-strategy-03.md))를 씁니다.

## 1. 제품 목록 (`/products`)

### 목적

회사가 만든 모든 제품을 한 화면에서 훑게 한다.

### 섹션 구성

```
┌─────────────────────────────────────────┐
│ 1. Page Heading                         │
│   - 제목: "제품"                         │
│   - 보조: "BLAH가 만들고 운영하는 정보 서비스" │
├─────────────────────────────────────────┤
│ 2. 제품 카드 리스트 (그리드)               │
│   - md+: 2 컬럼                         │
│   - 정렬 기준: 데이터 배열 순서           │
├─────────────────────────────────────────┤
│ 3. (옵션) 추가 예정 제품 안내 슬롯         │
│   "더 많은 정보 서비스가 준비 중입니다"     │
└─────────────────────────────────────────┘
```

### 카드 디자인

```
┌──────────────────────────────────────────┐
│ [상태 뱃지: 운영 중 / 베타 / 준비 중]      │
│                                          │
│ A.PAGO (아파고)                          │
│ — 광고가 아닌 정보, 추천이 아닌 사실        │
│                                          │
│ 식약처·FDA 인증 의료 AI와 도입 병의원·    │
│ 동물병원을 객관적으로 탐색하는 정보 플랫폼.   │
│                                          │
│ 분야: 헬스케어                            │
│                       [자세히 보기 →]     │
└──────────────────────────────────────────┘
```

- 카드 전체 영역이 `Link to="/products/:slug"`. 호버 시 그림자 강화.
- 상태 뱃지 색상: 운영 중 = `state.success` 톤 / 베타 = `state.warning` / 준비 중 = 회색.

### SEO

- `<title>`: `제품 | BLAH`
- description: 제품들의 요약을 합친 1문장.

## 2. 제품 상세 (`/products/:slug`)

### 목적

제품 하나를 처음 본 사람이 "**이게 뭐고, 누구한테 좋고, 어디로 들어가면 되는지**" 를 파악하게 한다.

### 섹션 구성

```
┌─────────────────────────────────────────┐
│ 1. Hero                                 │
│   - (제품 로고 또는 워드마크)              │
│   - 제품명 (영문 + 한글)                  │
│   - tagline (슬로건)                     │
│   - 상태 뱃지                            │
│   - CTA: [운영 사이트로] (외부)           │
├─────────────────────────────────────────┤
│ 2. 한 줄 정의 + 설명 (description)        │
├─────────────────────────────────────────┤
│ 3. 핵심 기능 (features)                  │
│   - 카드/리스트 형태로 3~5개 노출          │
├─────────────────────────────────────────┤
│ 4. 누구에게 도움이 되는가 (audiences)     │
│   - 태그 또는 불릿 리스트                  │
├─────────────────────────────────────────┤
│ 5. 약속 (promises, 있을 때만)            │
├─────────────────────────────────────────┤
│ 6. 다른 제품 보기                         │
│   - 같은 회사 다른 제품 1~2장 카드 노출    │
└─────────────────────────────────────────┘
```

### 데이터 매핑

| 섹션 | 사용 필드 |
|---|---|
| Hero 제품명 | `name`, `nameKo` |
| Hero 슬로건 | `tagline` |
| Hero 상태 | `status` |
| Hero 외부 CTA | `externalUrl` (없으면 버튼 숨김) |
| 한 줄 + 설명 | `summary` + `description` |
| 핵심 기능 | `features[]` |
| 누구에게 | `audiences[]` |
| 약속 | `promises?` |
| 다른 제품 | `products` 에서 현재 slug 제외한 나머지 |

### 슬러그 매칭과 404

- 라우트 파라미터 `:slug` 를 `getProductBySlug(slug)` 로 조회.
- 결과가 `undefined` 면 `<NotFound />` 를 그대로 렌더링하고 응답 시 200 으로 보내되 OG title 을 `404 | BLAH` 로 설정.
- 정적 호스팅 측 SPA fallback 설정은 [../deployment/build-and-deploy-01.md](../deployment/build-and-deploy-01.md) 참조.

### SEO

- `<title>`: `{제품명} | BLAH` (예: `A.PAGO | BLAH`)
- description: 제품 `summary` 그대로
- OG 이미지: 제품 전용이 있으면 사용, 없으면 사이트 기본 OG 사용
